# 多仓库工作流（设计）

> 状态：已实现（M22）。执行器与界面在 `src/composables/useWorkflowRun.ts`、
> `src/components/WorkflowRunBatchDialog.vue`、`src/components/ReposOverviewModal.vue`。

## 为什么

工作流原本只能对「当前仓库」执行。真实用法里有一大批流程是**同一件事在多个仓库重复**：
一早把 5 个 PWA 仓库都拉一遍、都建同名特性分支、都跑一次提交推送。逐个切过去点，
除了慢，更容易漏 —— 漏掉的那个往往就是最后发现冲突的那个。

## 入口

`所有仓库` 总览弹窗（顶栏「仓库总览」按钮）：

- 每行前面加勾选框；顶部「全选」是**三态**（全选 / 部分 / 无）。
- 勾选后顶部「运行工作流」变可用，点开下拉列出全部工作流 + 「管理工作流…」。
- 选一个工作流 → 关掉总览 → 打开**同一个**确认框（填运行时输入）→ 执行。

不新开第二个入口（工具栏的「工作流」仍然只作用于当前仓库），理由是同一个动作两个入口、
两套确认文案，用起来会分不清到底对谁生效。

## 语义（用户已拍板）

1. **勾选默认全不选**：打开总览不该有「一按就动别人仓库」的默认状态。
2. **某个仓库失败默认继续**跑其余的；确认框里有「某个仓库失败就停止后面的仓库」勾选（默认不勾）。
   理由：失败大多是那个仓库自己的事（同名分支已存在、有冲突），不该连累其他仓库。
3. **串行执行**，一个跑完再跑下一个。共用一套 git 索引锁与同一条网络，并发只会让失败更难归因
   —— 与「全部拉取」（`pullAllRepos`）同一取舍。
4. 进度用**新的批次弹窗**，不改单仓库的进度弹窗（那个的语义是「一个仓库的步骤时间线」）。

## 状态模型

执行内核 `runSteps(path, wf, run, inputs, prefixes, startBranch, fromIndex, guard)`：
不读 `repo` / `status`，仓库与起始分支全由调用方给。

- 单仓库入口：`guard = () => repo.value !== path ? "执行期间切换了仓库" : null`，
  每步开始前 + AI 生成提交信息之后各校验一次（AI 那 30 秒是最容易切仓库的窗口）。
- 批次入口：`guard = () => null`。批次在启动时就固定了 path 列表，用户切 tab 不该中止它。

批次状态 `wfBatch = { wf, rows, inputs, prefixes, stopOnFail, cur, done }`，
每行 `WfBatchRow = { path, name, startBranch, state, states, error, failIndex }`：

- `startBranch` **每行各记一份**，在该行开始前现取（总览里的分支可能已过时）。
  流程里的 `$起始分支` 与「切回起始分支」都靠它，多仓库时不能共用。
  **重试时沿用首轮记录，不重新现取** —— 失败点可能已在切分支之后，现取会把
  「失败现场所在的分支」当成起始分支，末尾 `switchBack` 就把仓库静默停在了错误分支上。
  这与单仓库 `retryFlow` 是同一条规矩。
- 行的 `state`：pending / running / done / fail / skipped（勾了「失败即停」时，后面那些标 skipped）。
- 失败行保留该行自己的 `states`，用来指出卡在哪一步；批次弹窗里展开可见。
- 重试只重跑**那一行**，且从头跑（失败可能停在切分支之后，接着跑会改变语义）。
- 批次期间 `busy = true`，挡住第二个批次与其它会写仓库的操作。

## 界面

批次弹窗一行一个仓库：状态图标 + 名字 + 状态文字 + 步骤进度 `3/5`；
正在跑的那一行自动展开，其余点名字展开；失败行（以及「失败即停」跳过的行）给「重试」，
非当前仓库给「切到该仓库」（批次跑着的时候也给 —— 切仓库是导航，不是写操作）。
执行期间可以关掉弹窗，流程继续（关的是可见性，不是 `wfBatch`）；浮层的 `open` 判的是
「弹窗可见」而不是「状态存在」，否则隐藏期间 Esc 会一直命中这一层，后面的设置页/总览关不掉。

## 不做的

- 并发执行（见上）。
- 批次结果持久化（关掉应用就没了；真要留痕，用每行起点的 reflog / 提交记录）。
- 条件步骤（「前一步失败才跑」这类），工作流仍是线性的。
- 跨仓库事务（一个仓库回滚不影响其它仓库；这是特性不是缺陷）。

## 已知风险

| 风险 | 现状 |
| --- | --- |
| 同名分支已存在 → 该仓库失败 | 默认继续，汇总里如实报 |
| merge 冲突 → 停在该仓库的冲突态 | 后续步骤不执行；汇总要显眼，用户需手工处理 |
| AI 生成提交信息 | 每个仓库各调一次，N 个仓库 = N 次调用 |
| 仓库被外部删除 | 该行报错，继续下一个 |
| 批次中途关窗/重启 | 已执行到的仓库不回滚 |
